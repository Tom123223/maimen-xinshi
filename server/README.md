# 麦门心事 · 本地体验版

一个能真的跑起来的版本：**输入你的心事 → 后端实时调麦当劳 MCP 取门店菜单 → 配一餐给你看**。
页面上的菜名、价格、营养是抓取那一刻的真实数据，不是写死的。

---

## 怎么启动

| 方式 | 操作 |
|---|---|
| 一键（推荐） | 双击 `start.bat`，浏览器会自动打开 `http://localhost:8765/?demo=1` |
| 命令行 | `node server.js`，然后手动打开 `http://localhost:8765` |
| 换个门店 | `set MCD_STORE=1990068 && node server.js` |
| 换端口 | `set PORT=9001 && node server.js` |

停服务器：在那个窗口按 `Ctrl + C`，或直接关掉窗口。

**Token 从哪来**：`server.js` 读的是 `~/.workbuddy/mcp.json` 里 `mcd-mcp` 的 Authorization，和 WorkBuddy 共用同一份配置。不复制、不写进页面、不进代码。

---

## 体验路径

1. 打开页面，左上角状态条会显示「实时数据 22/22 项 · 门店 1990102 · 15:03」——这说明后端已经连上 MCP 抓到真实菜单了；
2. 在左边写一句今天发生了什么（或用现成的 8 个心情标签）；
3. 点「生成我的心事餐」，依次得到：餐食搭配 → 快乐报告 → 热量报告 → 三位麦友审批 → 可复制的心事卡片；
4. 点状态条上的「重新抓取」，价格和菜名会按当前时刻的门店数据刷新一次（缓存 90 秒）。

想直接看结果态：地址栏加 `?demo=1`，会自动填入一段心事并跑完整个流程。

## 这一版的实时，实时在哪

| 环节 | 真实调用 | 落在页面哪里 |
|---|---|---|
| 门店菜单 | `query-meals`（storeCode + orderType + beType） | 22 个品项的名称与挂牌价 |
| 营养数据 | `list-nutrition-foods`（160 行紧凑表格文本，需按列名解析） | 热量、蛋白、脂肪、碳水、钠 |
| 时段判定 | 前端本地时间（与 `now-time-info` 同日历） | 早餐/午市/下午茶/晚市/深夜的热量上限 |

不在实时范围内、也不假装实时的：天气、星座、麦门签（按日期确定性生成，页脚已注明）。

## 营养匹配的三级策略

这是整个链路最容易出错的地方，也是我踩过的坑，记在这里备用。

换档后菜单会改菜名：原本叫「中薯条」，某个时段变成「薯条」；「热牛奶中杯」变成「牛奶」。这时按名称去营养库（160 行）里找就对不上了。

策略按优先级三级 + 一级回落：

| 级别 | 规则 | 例子 |
|---|---|---|
| 1 | 名称完全一致 | 板烧鸡腿堡 → 板烧鸡腿堡 |
| 2 | 归一化后一致（去括号、去 ™、去空格、去「汉堡」） | 纯牛奶(盒装) → 纯牛奶（盒装） |
| 3 | 去规格词后一致（中杯/大杯/盒装等） | 卡布奇诺 → 卡布奇诺中杯 |
| 回落 | 名称对不上时，**按门店编码**取同日快照里曾被精确匹配过的那一行 | 薯条(4810) → 中薯条 289 kcal |

刻意不做的事：**模糊包含匹配**。最开始写了 `key.includes(k)` 这种兜底，结果「牛奶」被配到「纯牛奶（盒装）」的 129 kcal，而它其实是「热牛奶中杯」的 176 kcal——数值看着合理，但错了。宁可显示「暂未获取」，也不猜。

接口返回里每个品项都带 `matchHow` 字段（`exact` / `normalized` / `size-tolerant` / `code-cache`），可以逐个核对匹配质量。

## 接口

```bash
# 健康检查
curl http://localhost:8765/api/health

# 按编码取实时数据
curl "http://localhost:8765/api/live?codes=1450,1406,4810"
```

`/api/live` 返回结构：

```json
{
  "ok": true,
  "at": "2026-10-21T07:03:12.000Z",
  "store": "1990102",
  "totalMenuItems": 110,
  "nutritionRows": 160,
  "match": { "exact": 15, "normalized": 2, "size-tolerant": 1, "code-cache": 4, "none": 0, "absent": 0 },
  "missingPrice": 0,
  "missingKcal": 0,
  "items": {
    "4810": { "name": "薯条", "price": 14.5, "kcal": 289, "p": 4, "f": 12, "c": 38, "na": 165,
              "matchedAs": "中薯条", "matchHow": "code-cache" }
  }
}
```

## 已知边界

- 只做决策辅助，不调用 `create-order` 等下单类工具；
- 只查门店 1990102（南京仙林金鹰）等自取门店，不涉及外送地址与账号信息；
- 菜单是门店实时档期数据，价格会变；演示前想确认数字，跑一次 `../scripts/check_snapshot.py`。
