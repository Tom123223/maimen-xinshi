# 一次完整会话示例

以下为麦门心事 v1.0 的完整输出示例，供评审核对输出格式与信息密度。

---

## 用户输入

> 今天加班到十点半，方案被客户打回来第三次了。走在路上看到麦当劳的灯还亮着，突然特别想吃点脆的。

---

## 第一步 · 心事解读

```
心事解读   情绪：疲惫 / 挫败　　能量：低　　进食动机：想被安慰，不是饿了
           关键词：脆
```

> 设计说明：不复述故事，只回一句判断。用户知道 AI 读懂了，但不必感觉被扒开。

---

## 第二步 · 餐食搭配

```
餐食搭配   麦辣鸡腿堡 + 中薯条 + 可口可乐（中）
           脆是今晚的关键词。你需要的不是营养均衡，是咬下去有声音的东西。
           预估 45.5 元
```

> 数据来源：`query-meals` 取门店菜单 → 按"脆"标签匹配 → `query-meal-detail` 确认套餐组成 → `calculate-price` 算价。价格随门店与活动变化，以实际查询结果为准。

---

## 第三步 · 双报告

### 快乐报告

```
快乐报告   情绪安抚度 82　　满足感预期 88　　心理热量 34
           结论：这顿不解决问题，但它让你有力气明天面对那个客户。
```

> "心理热量"是自造指标，指"这顿让你产生的愧疚念头强度"，越低越好。此指标不来自 MCP，属于 Skill 侧生成内容，已在文档中明确标注，不与真实营养数据混淆。

### 热量报告

```
热量报告   合计 1004 kcal
           蛋白质 27.6 g　脂肪 35.6 g　碳水化合物 139.5 g　钠 1392 mg
           占每日参考摄入约 50%，约为晚市参考量的 143%
           未超过晚市参考上限 1050 kcal
```

> 实际渲染以 `scripts/nutrition.py` 输出为准。上表数值取自下方联调实测。

**联调实测输出**（`python scripts/nutrition.py --json examples/sample_items.json --slot 晚市`）：

```
热量报告   合计 1004 kcal
           蛋白质 27.6 g　脂肪 35.6 g　碳水化合物 139.5 g　钠 1392.0 mg
           占每日参考摄入约 50%，约为晚市参考量的 143%
           注：香芋派 营养数据暂未获取，合计为已获取品项之和
```

> 说明：示例数据中"香芋派"未提供营养数值，报告正确地将其归入缺失项并排除在合计之外，**未做任何估算填充**。这是本项目的数据纪律。

---

## 第四步 · 麦友审批

```
麦友审批   阿宽：吃。第三次了，你不需要再改方案，你需要薯条。
           小满：汉堡可以，可乐换无糖。别让今晚的糖分带走明天的精神。
           老陈：你不是饿，你是想有个东西拿在手里。加个香芋派，慢慢吃。
           综合意见：准吃但改一处 —— 三个人都同意，改一处，加一份甜的。
```

> 三人立场必须真的有分歧：阿宽全无保留，小满提出具体替换，老陈点破情绪并加甜品。若三人意见一致，审批环节就失去存在意义。

---

## 第五步 · 心事卡片

**联调实测输出**（`python scripts/card.py --json examples/sample_session.json`）：

```
┌─ 麦门心事 · 2026-10-21 ──────────────────┐
│ 今天：方案被退回第三次                   │
│ 这一餐：麦辣鸡腿堡 + 中薯条              │
│       　可口可乐(中)                     │
│ 麦友意见：准吃但改一处                   │
│ 热量：1004 kcal　快乐指数 82（够用）     │
│ 可见时间：20 分钟（14:27 归档）          │
└──────────────────────────────────────────┘

20 分钟后，这顿吃完了。想补一句吗？
```

> 卡片边框经逐行显示宽度校验，中英文混排下始终等宽 44 列。

---

## 关于"20 分钟"

卡片上的 20 分钟**不是倒计时锁**，而是"这顿心事被看见的时间窗"。到期后卡片自动归档为一条心事后记，不阻断任何操作。

原始设想中的"公开投票 20 分钟决定能不能吃"已被有意移除，原因见 README「设计取舍」一节：真实投票需要自建后端，且 20 分钟窗口与"用户正饿着"直接冲突。v2.0 将以轻后端形式重新引入，见 Roadmap。
